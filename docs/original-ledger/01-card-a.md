1. Advancement squares: the port shows the raw advancement id as the name (objectives.rs to_tile), no description lore, no icon. The original shows the translated title (GREEN), the description and the display icon. Most visible gap in this slice (card-a-45).
2. Tile lore list name is always bingo.list.items (wire.rs tile_lore), so a square from another list reads the wrong list name (card-a-10).
3. No free spaces: a pool short of the distribution panics in the port, and the original fills with free spaces (card-a-08, card-a-09).
4. Achieved, locked, hidden and flashing looks differ: achieved is a tint, not a lime pane; is_locked and is_flashing are never set true, so the locked frame and the map flash never appear (card-a-16, card-a-17, card-a-65).
5. Same seed gives other cards and other shuffles than the original (card-a-21, card-a-38). Anyone comparing a seed against the original will see different squares.
6. Filters are absent: no /bingo filter command, no presets, no Include or Count filters, no filter tab completion (card-a-27 to card-a-34). Only the default -tedious -unobtainable applies. The unobtainable set is static (card-a-69).
7. Start-time soft warnings (team and player counts) are absent (card-a-35), so the original's warnings page has no port counterpart.
8. Stats squares ignore the data's min, max and relative values; the port hard-codes 1..max and relative (card-a-60). Shipped data may still differ from the original; check the shipped stats entries.
9. Reroll keeps tiers but not the null-tier rule, and objective progress on kept squares is unverified (card-a-40, card-a-41).
10. Display overrides from data (names, lore, items, decorations, rules) and %min%/%max%/%count% placeholders are absent (card-a-49, card-a-50); visible only if the original's display rules apply to shipped objectives.
11. Spawn-kit exclusion is partial: team kit and elytra items are not kept off the card (card-a-42).
