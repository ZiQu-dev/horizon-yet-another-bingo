- Tier-list weights: group weight = 1 / max(1, sum of group sizes containing the item); uncategorized values weight / 5.0 (TierListConfig.kt:92-112).
- Caches: 5 seconds (ObjectiveListService.kt:9, TagService.kt:11).
- Opponent and inverse both use permanent state; Inverse data default permanent=true (`objectives.rs` mirrors this).

### Parity risks
1. Inverse squares read "Not X" in the port instead of "Never get X", and no objective name is italic (card-b-01, card-b-05). Visible on every never_get square the player hovers.
2. Opponent, scoreboard and some_of squares are missing (card-b-08, 11, 16). If the bundled challenge or advancement tier lists contain them, those squares are absent or replaced on the card (count not verified: grep for opponent/scoreboard in the port's challenge catalog before deciding).
3. Tile progress is binary in the port; the original draws a partial fill for one_of, all_of, stats, scoreboard and item squares with a count (card-b-13).
4. Stats squares print raw ids ("minecraft:stone: 1") instead of "Mined Stone: 1" (card-b-14).
5. one_of / all_of names list every entry; the original shows the first entry plus ", …" (card-b-09).
6. Item squares with count > 1 (" x N" and count-based holding) are not supported; port holds an item on one copy (card-b-17, card-b-19).
7. Difficulty preset names are lowercase and untranslated in the port (card-b-35).
8. Random draws: the port uses its own RNG, so the same seed does not reproduce the original's card (tier-draw order and weights match, card-b-32).
9. Held-item exclusion for new cards (card-b-21) is UNSURE in the port; verify against the caller in CardService.
10. Filter/tag features (card-b-26..29) and tier-list editing (card-b-38) are absent: the port has no filter menu (low visibility, but a whole original feature).
