### Parity risks
1. Options changed during a game are refused by the port (session.rs:2627-2629) but accepted by the original, and the port prints the full options text instead of a "Set 'X' = Y" line (OptionsService.kt:94-128). Visible to every admin using /bingo commands.
2. `/bingo options` text (session.rs:2636-2662) is a single plain sentence. The original summary has clickable grey/yellow rows for mode, features, goal, end-when (only if not first win), time limit, card difficulty and filter (OptionsService.kt:463-552). Difficulty, filter and time-limit lines are missing.
3. Client HUD switches that are stored but do nothing: showMultipleCards (config.rs:65), messageFromOtherTeams (config.rs:68), cardOverlap z (config.rs overlap_z has no caller), showQuickStartButton (no title button). They appear in the settings screen and look broken.
4. Modes: one Mode enum, so lockout and inventory cannot be combined (options.rs:33-41); the original keeps lockout and inventory together and only makes inventory and consume exclusive (OptionsService.kt:178-184).
5. Night vision for spectators and after the game is hard-coded on (session.rs:209-211); the original reads BingoConfig.nightVisionInSpectator and nightVisionInPostgame.
6. Start timing: no 100-tick (5 s) delay before countdown (BingoConfig.kt:73-74) and no switch for the ready-wait rules. The countdown starts sooner than in the original.
7. Reset-on-empty fixed at 100 ticks (session.rs:1068) with no switch for resetWhenEveryoneDisconnects (BingoConfig.kt:78-79).
8. Defaults: `/bingo defaults` resets to hard-coded Options::default() (session.rs:1247) and ignores game-options-default.json (ConfigService.kt:13), so a server admin's edited defaults never apply.
9. Broken config: the original overwrites an unreadable config with defaults (ConfigManager.kt:54-63); the port keeps the broken file until the next save (config.rs from_json; lib.rs:632).
10. Time limit: no restore after reset (RestoreOption.kt:43-48) and no add-elapsed rule while playing (OptionsService.kt:355-366).
11. Unlock recipes (BingoOptions.kt:32) has no port counterpart; the recipe book stays locked.
12. Editable data: tierlists and tags can be edited on disk in the original (TrackedFileService.kt); the port compiles them in, so a player who edits them sees no change.
13. Card filter (OptionsService.kt:154-168) and its presets (BingoConfig.kt:14-15) are absent, so the filter line and `/bingo filter` cannot exist.
